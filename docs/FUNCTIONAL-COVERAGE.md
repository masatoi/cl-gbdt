# Functional Coverage

Every symbol `cl-gbdt`, `cl-gbdt/lightgbm` and `cl-gbdt/xgboost` export has a position here:
either the functional suite's own sources name it, or a row below says why they do not.
`tools/ci/check-functional-coverage.lisp` fails the build when a published symbol has neither, so
a symbol cannot reach the public surface without the project taking a position on how it is
proven.

**Covered is not written down.** The checker derives it: a symbol is covered when it appears in
some top-level form of a `tests/functional/*.lisp` file, outside that file's own package form.
Recording it here as well would give it a second home to go stale in -- the same rule
`ffi-spec/BINDING-COVERAGE.md` follows for `wrapped`.

Neither are counts or percentages. Coverage in this project is guaranteed by classification --
every symbol has a recorded position -- not by a number. The checker prints the live counts on
every run.

**What being covered does NOT mean.** That the suite's source names a symbol is not that the
symbol's contract is exercised. A condition named in a `handler-case` clause counts. So does a
function called once inside a fixture nothing asserts on. This file records where every published
symbol stands; it does not measure how well anything is tested, and a green run is not evidence
that it does.

The heading a row sits under is part of what the checker reads. It recognises exactly two
spellings: the literal `## Unproven`, and any heading beginning `## Exempt`. A row under anything
else -- a renamed heading, a new one, or one preceding the file's first `## ` heading -- fails the
build rather than landing silently in either bucket.

Each `## Exempt` heading carries its section's argument, so a row's Note is for what the heading
does not already say. A symbol whose argument fits none of the headings belongs under
`## Unproven`; adding a heading also means editing the checker's vocabulary, which is a deliberate
act rather than a matter of writing prose.

Rows name the symbol the way `docs/API-REFERENCE.md` heads its entries -- qualified by the
shortest public package that exports it -- so a reader can move between the two files.

Notes are Markdown, so a code span closes with a backtick on both ends (`` `foo` ``); Lisp
source's `` `foo' `` convention -- an opening backtick and a closing apostrophe -- is not used
here, since an unclosed backtick leaves the rest of the row unrendered as code.

## Exempt: proven without a shared library

The symbol's whole contract is computation the shared library takes no part in, and the layer 1
suite proves it. A functional test here would open a library, ignore it, and assert what
`tests/*.lisp` already asserts -- three minutes of CI for no additional evidence.

A row belongs here only when the layer 1 test exists. "Nothing calls the library" is half the
argument; the Note carries the other half, by naming the test that does the proving.

## Exempt: only reachable through a broken shared library

Narrower than "proven without a shared library" above, and not to be confused with it: the
symbol's true signal path needs a real shared library -- just a broken one, missing a function
this project requires after otherwise loading successfully. Neither vendored library,
`liblightgbm.so` or `libxgboost.so`, is ever in that state, and nothing in this suite builds or
loads a deliberately incomplete one, so no functional test -- real or hypothetically
constructed -- has ever reached this path. That is a claim about reachability, not a claim that
a fabricated-condition test stands in for it: where one is cited below, it is offered only for
what it actually proves, the condition object's own report contract in isolation, not the real
`initialize-backend` signal path, which nothing here exercises.

`cl-gbdt:backend-library-load-failed` (see "Exempt: proven without a shared library" above) is
NOT the same shape despite a surface resemblance ("only happens when a load fails"): when IT
fires, `cffi:load-foreign-library` has already rejected the candidate path, so zero bytes of any
shared library are ever mapped into the process -- the heading above's claim holds literally.
Here, by contrast, a real library must already be mapped in and successfully answering symbol
queries before this condition can fire at all.

| Symbol | Why the real signal path is unreachable here |
|---|---|
| `cl-gbdt:missing-foreign-symbols` | Signalled from both backends' `initialize-backend` when `probe-foreign-symbols` finds a `*required-symbols*` name unresolved in the library that was JUST loaded successfully -- true only of a version-mismatched library, which neither vendored `.so` is; `with-backend-library` always loads the real, matching one. `tests/conditions.lisp`'s `missing-foreign-symbols-reports-names` directly instantiates the condition, `(error 'cl-gbdt:missing-foreign-symbols :backend :lightgbm :names '("LGBM_GetMaxThreads" "LGBM_SetMaxThreads"))`, with no library loaded, and checks the printed report contains both names and the count `"2"`. That proves the condition's own report contract; it says nothing about the real path through `initialize-backend`, which no test, layer 1 or functional, exercises. |
| `cl-gbdt:missing-foreign-symbols-names` | Same absence of a real signal path as the row above. The same `missing-foreign-symbols-reports-names` test is the only place this reader is exercised, and only through a fabricated instance -- the same shape of evidence this file declines to accept for `foreign-call-error-code`, where the condition ALSO fires for real elsewhere and goes unread there. The difference here is that `missing-foreign-symbols` never fires for real anywhere in this suite, so there is no competing real-world instance for the fabricated one to fall short of; it is the only evidence this reader could have without this project shipping a deliberately broken second library. Within that limit, it does prove something: both names and the count `"2"` appear in the printed report, which only holds if this reader returns both. |
